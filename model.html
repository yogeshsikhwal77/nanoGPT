01 — The Model Architecture (The GPT Class)

The Forward Pass Pipeline

The `GPT.forward()` method manages the macro-structure. Every stage receives a tensor shaped (Batch, Time, Channels) and preserves it — until the final LM Head maps it to vocab_size. Click a stage to see the corresponding PyTorch logic.

Token + Position Embedding

Every token id looks up a row in a vocab_size × dim matrix. Simultaneously, its sequential position (0 to T−1) looks up a row in a context_len × dim matrix. The two vectors are simply added together.

self.tok_emb = nn.Embedding(cfg.vocab_size, cfg.dim)
self.pos_emb = nn.Embedding(cfg.context_len, cfg.dim)
# ... inside forward() ...
pos = torch.arange(T, device=idx.device)
x = self.tok_emb(idx) + self.pos_emb(pos)
Learned, not sinusoidal: Notice we use `nn.Embedding` for positions. One distinct trainable row per position. Because of this, `cfg.context_len` is a hard physical ceiling; the model literally does not have parameters to read position `context_len + 1`.

The Transformer Block

The core of GPT is the repeated `Block` class. It enforces the "Pre-norm Residual" architecture, which allows gradients to flow effortlessly back to the embeddings through the addition (`+`) operations.

class Block(nn.Module):
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        self.ln1 = nn.LayerNorm(cfg.dim)
        self.attn = CausalSelfAttention(cfg)
        self.ln2 = nn.LayerNorm(cfg.dim)
        self.mlp = MLP(cfg)

    def forward(self, x):
        x = x + self.attn(self.ln1(x))
        x = x + self.mlp(self.ln2(x))
        return x
Read x = x + attn(ln1(x)) as: "add what attention noticed to what was already there." The residual stream `x` acts as a central highway. Sub-layers only read from it (after normalization) and add their findings back into it.

Final LayerNorm

After `cfg.layers` blocks, the residual stream has accumulated massive variance. A final `LayerNorm` stabilizes the tensor right before predicting the vocabulary.

self.ln_f = nn.LayerNorm(cfg.dim)
# ...
for block in self.blocks:
    x = block(x)
x = self.ln_f(x)

LM Head & Weight Tying

The linear layer that maps our `dim` channels to `vocab_size` scores shares the exact same memory as the input `tok_emb`. This is a classic trick to save parameters.

self.lm_head = nn.Linear(cfg.dim, cfg.vocab_size, bias=False)
# weight tying: LM head shares token embedding matrix
self.lm_head.weight = self.tok_emb.weight

If `vocab=10000` and `dim=384`, this tying saves ~3.84 Million parameters. It also ensures the model learns a unified representation for "reading" a word and "writing" a word.

Cross-Entropy & SFT Masking

By flattening the batch and time dimensions, we can calculate loss efficiently. NanoGPT also uses `-100` natively to ignore prompt tokens during supervised fine-tuning (SFT).

loss = None
if targets is not None:
    loss = F.cross_entropy(
        logits.view(-1, logits.size(-1)),
        targets.view(-1),
        ignore_index=-100,  # SFT masking works for free
    )
The `ignore_index=-100` tells PyTorch to completely skip those targets when computing the gradient. The model.py code doesn't need to know if it's fine-tuning or pre-training; it just obeys the `-100`s passed by the dataset loader.

02 — Inside CausalSelfAttention

Multi-Head Causal Attention

Tokens query each other to understand context. To prevent tokens from "cheating" and looking at the future during training, a lower-triangular causal mask is enforced.

def forward(self, x):
    B, T, C = x.shape
    q, k, v = self.qkv(x).split(C, dim=2)
    # (B, T, C) -> (B, heads, T, head_dim)
    q = q.view(B, T, self.heads, self.head_dim).transpose(1, 2)
    k = k.view(B, T, self.heads, self.head_dim).transpose(1, 2)
    v = v.view(B, T, self.heads, self.head_dim).transpose(1, 2)

    # PyTorch's ultra-fast Flash Attention implementation
    y = F.scaled_dot_product_attention(q, k, v, is_causal=True)

    y = y.transpose(1, 2).contiguous().view(B, T, C)
    return self.proj(y)
■ Token can attend here    ■ Masked out (-inf)
The Multi-Head Dance: We project `x` into a massive `3 * dim` tensor, chunk it into Q, K, and V, and reshape it into `heads`. Because `head_dim` = `dim / heads`, the math perfectly balances out. The `transpose(1, 2)` swaps Time and Heads, so matrix multiplications happen across the sequence.

03 — Inside The MLP

The Feed-Forward Network

While Attention is about tokens communicating with each other, the MLP is where tokens process what they've learned individually. It expands the channel dimension by 4x to do complex reasoning, then compresses it back down.

class MLP(nn.Module):
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        # Expands dim (e.g. 384 -> 1536)
        self.fc1 = nn.Linear(cfg.dim, 4 * cfg.dim, bias=False)
        # Contracts back (e.g. 1536 -> 384)
        self.fc2 = nn.Linear(4 * cfg.dim, cfg.dim, bias=False)

    def forward(self, x):
        return self.fc2(F.gelu(self.fc1(x)))
GELU Activation: `F.gelu` (Gaussian Error Linear Unit) is the standard activation for GPTs. It's smoother than ReLU and allows small negative values to flow through, which prevents dead neurons during training.

Also note `bias=False`. Modern LLMs drop biases in Linear layers to save memory and slightly increase throughput without losing performance.

04 — Model Initialization

Scaling the Residual Gradients

If you initialize deep networks improperly, the variance explodes. The `GPT` class includes a crucial, specific normalization tweak for layers that write directly back into the residual stream.

self.apply(self._init_weights)
# smaller init on layers that write into the residual stream
for name, p in self.named_parameters():
    if name.endswith("proj.weight") or name.endswith("fc2.weight"):
        nn.init.normal_(p, mean=0.0, std=0.02 / math.sqrt(2 * cfg.layers))

@staticmethod
def _init_weights(module):
    if isinstance(module, nn.Linear) or isinstance(module, nn.Embedding):
        nn.init.normal_(module.weight, mean=0.0, std=0.02)
The Base Init: Linear layers and embeddings start with a Gaussian distribution of `std=0.02`.
The Residual Scaling: `proj.weight` (from Attention) and `fc2.weight` (from MLP) are the final steps before `x = x + layer(x)`. Because we add to the stream `2 * layers` times, we scale their initialization down by `1 / sqrt(2 * layers)` to keep the variance at ~1.0 at initialization.
